# RT-MLIDS
### Ensemble machine-learning intrusion detection on NSL-KDD, with black-box adversarial evaluation

[![CI](https://github.com/brigghouse/RT-MLIDS/actions/workflows/ci.yml/badge.svg)](https://github.com/brigghouse/RT-MLIDS/actions/workflows/ci.yml)
[![Python](https://img.shields.io/badge/Python-3.11+-3776AB?style=flat-square&logo=python&logoColor=white)](https://python.org)
[![License](https://img.shields.io/badge/License-MIT-green?style=flat-square)](LICENSE)

RT-MLIDS is a research codebase for network intrusion detection: a stacked ensemble (Random Forest + XGBoost, logistic-regression meta-learner trained on out-of-fold predictions), mutual-information feature selection, SMOTE, SHAP explanations, a streaming inference pipeline (Kafka consumer or any iterable), and a black-box adversarial evaluation with the Adversarial Robustness Toolbox.

Everything reported below is regenerated by one command (`python rt_mlids_experiment.py`) and stored in [`results/results.json`](results/results.json). The accompanying paper is in [`docs/`](docs/).

## Results (NSL-KDD, full KDDTest+ — 22,544 records)

Mean ± std over 3 seeds. The train/test split is the official fixed one, so the std reflects training randomness only, not dataset variability. `*` SVM trained on a 30,000-record stratified subsample.

**Attack vs normal (binary)** — the view relevant to an IDS operator:

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Random Forest | 75.38 ± 0.23 | 92.31 ± 0.27 | 61.90 ± 0.46 | 74.11 ± 0.31 |
| XGBoost | 79.24 ± 0.08 | 96.71 ± 0.01 | 65.76 ± 0.14 | 78.29 ± 0.10 |
| SVM (30k subsample)* | 73.08 ± 0.27 | 91.44 ± 0.05 | 58.15 ± 0.49 | 71.09 ± 0.38 |
| Stacked Ensemble | 78.17 ± 0.19 | 96.71 ± 0.02 | 63.82 ± 0.33 | 76.89 ± 0.24 |

**Five classes (dos / normal / probe / r2l / u2r), weighted averages** (weighted recall equals accuracy):

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Random Forest | 74.14 ± 0.22 | 78.68 ± 0.21 | 74.14 ± 0.22 | 70.31 ± 0.25 |
| XGBoost | 77.64 ± 0.40 | 82.62 ± 0.41 | 77.64 ± 0.40 | 74.35 ± 0.49 |
| SVM (30k subsample)* | 71.75 ± 0.17 | 73.19 ± 0.37 | 71.75 ± 0.17 | 67.09 ± 0.15 |
| Stacked Ensemble | 77.00 ± 0.28 | 82.46 ± 0.22 | 77.00 ± 0.28 | 73.30 ± 0.36 |

Take-aways: XGBoost is the best model here (binary F1 78.29 ± 0.10%, five-class accuracy 77.64 ± 0.40%); the stacked ensemble is about one point behind (76.89 ± 0.24%, 77.00 ± 0.28%) and much slower, so stacking does not pay off on this benchmark. Precision is high for both tree models but recall on attack types unseen in training is only ~64–66%, which is the real limitation. Accuracy is far below the 99% reported on easier splits because KDDTest+ contains attack types absent from training.

### Latency

| Path | µs / flow | flows / s |
|---|---|---|
| Random Forest (model only) | 102.3 | 9,778 |
| XGBoost (model only) | 12.4 | 80,398 |
| Stacked Ensemble (model only) | 121.4 | 8,235 |
| Stacked Ensemble, end-to-end replay (preprocess + infer + alert, no Kafka) | 150.2 | 6,659 |

Single thread on a 2-vCPU cloud container. "End-to-end replay" pushes raw test records through the streaming code path without Kafka transport or live feature extraction; it is not a production latency guarantee. Regenerate with `python run_latency.py`.

### Black-box adversarial evaluation

HopSkipJump and ZOO (ART, `BlackBoxClassifier`, probabilities only) on a seeded random sample of KDDTest+. Raw ART output can be an invalid NSL-KDD record, so accuracy is also reported after *projection* to valid records (clip to the scaled range, round one-hot columns). Budgets: XGBoost HSJ 20 iterations / ZOO 100; ensemble HSJ 5 / ZOO 20 (reduced because each query evaluates RF + XGBoost + meta-learner), (each query evaluates RF + XGBoost + meta-learner) and a smaller sample.

| Model | Condition | Accuracy [95% CI] | n |
|---|---|---|---|
| XGBoost | clean | 70.0% [48–85] | 20 |
| XGBoost | HopSkipJump, raw | 15.0% [5–36] | 20 |
| XGBoost | HopSkipJump, projected | 35.0% [18–57] | 20 |
| XGBoost | ZOO, raw | 10.0% [3–30] | 20 |
| XGBoost | ZOO, projected | 15.0% [5–36] | 20 |
| Stacked Ensemble | clean | 70.0% [48–85] | 20 |
| Stacked Ensemble | HopSkipJump, raw | 5.0% [1–24] | 20 |
| Stacked Ensemble | HopSkipJump, projected | 35.0% [18–57] | 20 |
| Stacked Ensemble | ZOO, raw | 40.0% [22–61] | 20 |
| Stacked Ensemble | ZOO, projected | 45.0% [26–66] | 20 |


Read these as indicative: samples are small (n = 20 for XGBoost, 20 for the ensemble) and intervals are wide; feature dependencies in NSL-KDD (e.g. rates derived from counts) are not enforced, so projected numbers are still an upper bound on attacker success. Regenerate with `python run_adversarial.py`.

## Pipeline

```
raw NSL-KDD record (41 features)
  → one-hot (protocol_type, service, flag)  → 122 columns (train+test vocabulary)
  → Mutual Information top-30 (fit on train)
  → MinMax scaling (fit on train)
  → SMOTE (training folds only)
  → Random Forest (500 trees, depth 15) + XGBoost (300 est., lr 0.05, depth 6)
  → logistic-regression meta-learner on out-of-fold probabilities (3-fold)
  → alert if predicted class ≠ normal and confidence ≥ θ (θ = 0.85, a fixed operating point)
```

The streaming front end (`src/pipeline/stream_processor.py`) consumes JSON records from Kafka (optional dependency) or any iterable, applies the same fitted preprocessing, classifies micro-batches and emits alerts; it is unit-tested with a fake consumer.

## Install and run

```bash
git clone https://github.com/brigghouse/RT-MLIDS.git && cd RT-MLIDS
pip install -r requirements.txt          # add -r requirements-dev.txt for tests, notebooks, Kafka
# put KDDTrain+.txt and KDDTest+.txt in data/NSL_KDD/  (see data/README.md)
python rt_mlids_experiment.py --no-adv --save-model models/saved/rt_mlids.pkl
python run_adversarial.py            # slow: black-box attacks query the model repeatedly
python run_latency.py                # run on an otherwise idle machine
python -m src.evaluate --model models/saved/rt_mlids.pkl
python -m pytest -q
```

Python 3.11+. The experiment takes roughly 10 minutes per seed on 2 vCPUs; the adversarial script takes tens of minutes. Note the PyPI package for ART is `adversarial-robustness-toolbox`.

## Repository layout

```
src/data.py            NSL-KDD loading, complete label map, preprocessing
src/models/ensemble.py out-of-fold stacked ensemble
src/metrics.py         binary + multi-class metrics, Wilson CI, latency
src/adversarial/       black-box attacks + validity projection
src/pipeline/          stream processor, alert engine
rt_mlids_experiment.py all classification results (3 seeds), SHAP
run_adversarial.py     adversarial evaluation
run_latency.py         latency benchmark
results/               results.json, adversarial.json, latency.json
notebooks/             read the JSON results
tests/                 pytest suite (runs in CI)
```

## Limitations

NSL-KDD is dated (1999-era traffic) and has one fixed split; U2R/R2L per-class results are noisy; adversarial samples are small; latency is a single-machine micro-benchmark; no comparison with other published IDS models under this protocol; CIC-IDS-2018 is **not** evaluated (future work).
